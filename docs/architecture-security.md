# StreamArena architecture and trust boundaries

This document is the security contract for the self-hosted backend, browser,
mobile client, SQLite stores, media subprocesses, provider network, and the
live-HLS Cloudflare Worker. A change that crosses one of these boundaries must
add a focused regression test and remain in the mandatory `bun run check` gate.

## Durable state and replay model

`users.sqlite` is authoritative for accounts and user state. The resolver cache
database is regenerable and never owns accounts. Watch-progress and
continue-watching mutations carry a client `updatedAt` version generated by a
monotonic, local high-water clock. SQLite applies last-write-wins only when the
incoming version is at least the stored version.

Deletes write a durable tombstone in the same SQLite transaction as the row
deletion. An offline request older than that tombstone is acknowledged but
cannot resurrect the row. A genuinely newer write clears the obsolete
tombstone. Tombstones are retained for 180 days, bounding storage while covering
long-offline clients. Series-wide cleanup remains a server-owned canonicalizing
operation; clients should send the series identity with the deletion.

Schema changes are append-only named migrations. SQL and its ledger checksum
commit in one transaction. Reusing a migration ID with different SQL or a
partially failing migration stops startup without recording or retaining partial
DDL. The rollback fixture is part of the Rust test suite.

## Browser and account boundary

Sessions are HttpOnly, SameSite cookies. State-changing browser requests are
also checked using Fetch Metadata and `Origin`: an explicit cross-site request,
null origin, or mismatched origin is rejected. Requests without browser
provenance remain available to the native app and trusted CLI clients; they
still require normal authentication.

Password verification is Argon2 on a bounded blocking pool. Sliding-window
budgets cap total attempts and a separate per-email exponential cooldown slows
successive failures without sleeping an async worker. Password changes,
disablement, promotion, and demotion revoke existing sessions so authorization
cannot change underneath a bearer cookie.

## Provider and media boundary

Provider URLs remain server-selected and bounded by provider-specific time and
concurrency budgets. Media subprocesses are time-bounded and cleanup must be
cancellation-safe. Provider responses must not be treated as trusted markup or
as authorization for a different host. New provider adapters require malformed
payload, timeout, redirect, and private-host tests before being enabled.

Native provider HTTP uses a dedicated client that never follows redirects and
rejects an entire direct DNS answer when any returned address is private, local,
reserved, or documentation-only. Only exact compiled provider control-plane hosts
may use the optional outbound proxy; provider-returned CDN hosts and admin-added
providers stay on the guarded direct path, so remote proxy DNS cannot bypass
the policy. The normal shared client remains available for explicitly configured
self-hosted services such as Torznab. Provider-scoped semaphores sit inside the
global resolver limit, so a saturated upstream cannot consume every resolver
slot.

Cleanup guards own uncommitted torrent handles and partial direct-download/HLS
files. Dropping a request future schedules torrent removal and removes partial
files; successful insertion or atomic rename explicitly disarms the guard.

## Live-HLS edge boundary

The Worker accepts only backend-minted, expiry-bound HMAC URLs. HTTPS public
hostnames are required even after every manual redirect; IP literals,
localhost/internal suffixes, worker self-recursion, excess redirects, oversized
buffered playlists/PNG segments, excessive playlist lines, long URIs, and
manifest fan-out are rejected. Origin relay bases must be exact credential-free
origins. Playlist and PNG compatibility paths buffer only under hard byte caps;
ordinary media responses stream through.

Cloudflare Workers do not expose a portable DNS-resolution API for inspecting
resolved addresses. HTTPS certificate validation, backend-only URL minting,
lexical host rejection, manual redirect validation, and the origin allowlist are
therefore the enforced controls. Do not relax the signed-URL boundary to accept
arbitrary client URLs.

## Verification boundaries

`bun run check` proves local formatting, Clippy, dependency audit, frontend
syntax/build/architecture, Rust tests, Worker adversarial tests, Playwright
smoke, benchmark contract coverage, and a bounded isolated startup sample. Live
resolver and concurrent-playback benchmark commands enforce explicit p95/startup
budgets when a provider/media fixture is available. The local gate does not
prove production secrets, public DNS, Cloudflare routes, the Mac
mini runtime, or real licensed provider availability. Those require the
explicit deployment and live checks documented in `README.md`.
